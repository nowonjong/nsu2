# NSU2 One Branch Short Handoff - 2026-04-13

이 문서는 현재 `C:\SignProject` 기준으로 주요 파일 위치, 실험 진행 방식, 핵심 결과를 빠르게 이어받기 위한 짧은 요약이다.

## 1. 현재 프로젝트 방향

최종 비교 프레임은 다음 3축이다.

- bare hand + vision
- glove + vision
- glove + fusion

현재 가장 중요한 실험 흐름은 `glove + vision`과 `glove + fusion`을 같은 실제 입력 조건에서 비교하여, 비슷한 수어 동작에서 센서 데이터가 실사용 성능을 얼마나 보완하는지 확인하는 것이다.

주의할 점:

- `stable hybrid`는 현재 가장 안전한 fusion baseline / 최종 구조 후보이지, 절대적인 최종 확정 모델이라고 단정하지 않는다.
- 최종 지표 프레임은 `Offline` vs `Practical` 중심으로 정리한다.
- `Realistic offline`은 중간 분석용으로 남길 수 있지만, 현재 보고의 메인 축에서는 제외한다.

## 2. 주요 실행/학습 파일

- `gpt_collect.py`
  - 맨손/비전 쪽 데이터 수집에 사용했던 collect 계열 파일.

- `nsu_collect.py`
  - 장갑 착용 상태에서 vision + sensor 데이터를 수집하는 핵심 collect 파일.
  - 현재 18개 단어 수집 기준으로 맞춰져 있다.

- `gpt_run.py`
  - vision-only run 파일.
  - 현재는 공식 Practical 평가 수집용이 아니라 보조 실행/확인용에 가깝다.

- `nsu_run_fusion_v6_overlap_hold.py`
  - 공식 Practical capture 수집용 run 파일.
  - GT 라벨 지정, 18개 단어 표시, vision + sensor capture 저장, 약한 hold/overlap 안정화 로직이 포함되어 있다.
  - Practical 비교는 앞으로 이 파일로 저장한 capture만 공식 입력으로 사용한다.

- `nsu_train.py`
  - 장갑 기반 모델 학습 파일.

## 5. 현재까지 얻은 핵심 결론

### Offline vs Practical

- Offline LSTM 평가에서는 vision-only가 더 높다.
- Practical 평가에서는 네 세트 모두 fusion이 vision-only보다 높다.
- 특히 학습 데이터 수집에 참여하지 않은 사람(Out, Out-2)에서 fusion의 장점이 더 크게 드러난다.

정리하면, vision-only는 잘린 샘플 기반 offline 환경에서는 강하지만, 실제 run 환경에서는 사용자 차이와 자세/속도/손 위치 변화에 취약하다. Fusion은 센서의 물리적 정보를 함께 사용해서 Practical 환경에서 더 안정적이다.

### Practical 결과 요약

- Practical-In: fusion이 vision보다 Accuracy 기준 `+0.1389`
- Practical-In-2: fusion이 vision보다 Accuracy 기준 `+0.0417`
- Practical-Out: fusion이 vision보다 Accuracy 기준 `+0.3195`
- Practical-Out-2: fusion이 vision보다 Accuracy 기준 `+0.1667`

따라서 메인 스토리는 “offline 수치가 높은 vision-only가 실제 환경에서도 항상 더 좋은 것은 아니며, 장갑 센서 fusion은 Practical 환경, 특히 미참여자 조건에서 강건성을 보완한다”로 잡는 것이 안전하다.

## 8. Practical 수집 프로토콜

상세 문서:

- `PRACTICAL_PROTOCOL.md`

공식 Practical 수집 기본 방식:

1. PowerShell 또는 VSCode 터미널에서 capture 저장 경로를 지정한다.
2. 같은 터미널에서 `nsu_run_fusion_v6_overlap_hold.py`를 실행한다.
3. GT 라벨을 맞춘 뒤 단어별 4회씩 수행한다.
4. 잘못된 GT 또는 명백한 실수 샘플은 즉시 삭제한다.
5. 종료 후 captures/reports 개수와 GT 분포를 확인한다.

예시:

```powershell
$env:NSU_RUN_DEBUG_CAPTURE_DIR='C:\SignProject\experiments\live_eval\practical_out_2\captures'
& C:\SignProject\myenv\Scripts\python.exe C:\SignProject\nsu_run_fusion_v6_overlap_hold.py
```

주의:

- 터미널을 껐다 켜면 `$env:NSU_RUN_DEBUG_CAPTURE_DIR` 설정은 사라진다.
- 따라서 run을 다시 시작할 때는 반드시 저장 경로를 다시 지정해야 한다.

## 9. 다음 우선순위

바로 다음에 하면 좋은 작업은 다음 순서다.

1. FPS / latency 측정
   - 교수님 질문 대비: “센서 fusion 때문에 실시간성이 떨어지지 않는가?”에 답해야 한다.
   - vision-only vs fusion의 FPS, loop time, inference time을 비교한다.

2. Sensor ablation 분석
   - full fusion, sensor-zero, flex 제거, IMU 제거 등을 비교한다.
   - 어떤 센서가 어떤 그룹에서 도움을 줬는지 설명할 수 있게 만든다.

3. Hardware architecture 정리
   - 센서 -> MCU -> PC Python -> model 흐름도
   - baudrate, sampling rate, 동기화 방식, 비용/전력 등을 정리한다.

4. Hold / overlap 안정성 분석
   - 현재 Practical은 one-shot 60 frame capture 중심이라 flicker 분석 우선순위는 낮다.
   - 발표에서 실시간 안정화 기여를 강조하려면 output flicker rate 전후 비교를 추가로 만들 수 있다.

## 10. 최종 발표/보고서에서 안전한 표현

좋은 표현:

- “Offline 평가에서는 vision-only가 더 높았지만, Practical 평가에서는 fusion이 네 세트 모두에서 더 안정적이었다.”
- “장갑 센서는 특히 미참여자 조건과 비슷한 동작 그룹에서 vision-only의 취약점을 보완했다.”
- “Fusion 개선폭은 그룹별로 다르며, 방향/순간 손모양/추가 동작/경로 차이 그룹에서 더 크게 나타났다.”

피해야 할 표현:

- “stable hybrid가 최종 확정 모델이다.”
- “실시간 문제 원인은 class mapping 버그였다.”
- “센서 fusion이 모든 상황에서 무조건 압도적으로 좋다.”
- “Realistic offline이 공식 최종 지표다.”

현재 가장 방어력 있는 결론은 다음이다.

> Vision-only는 offline score는 높지만 실제 사용 조건에서 흔들릴 수 있고, glove fusion은 같은 Practical 입력 조건에서 더 안정적인 성능을 보였다. 특히 미참여자와 유사 수어 그룹에서 센서 정보의 보완 효과가 확인되었다.
