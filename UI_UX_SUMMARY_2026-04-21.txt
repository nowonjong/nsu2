UI / UX 정리 메모
작성일: 2026-04-21
프로젝트: C:\SignProject
대상 파일: nsu_run_fusion_v6_overlap_hold.py

1. 배경
- 하드웨어 완성도가 아주 높지 않기 때문에, 발표/심사에서는 소프트웨어 UI/UX로 시스템 완성도와 센서 융합의 존재감을 보완하려는 목적이 있었음.
- 기존 run 화면은 640x480 카메라 영상 위에 OSD를 얹는 구조였고, 정보 전달력은 있었지만 발표용 쇼케이스 느낌은 약했음.

2. 초기에 고민했던 3가지 루트
- 루트 1: OpenCV 기반 현 구조를 유지하면서 대형 대시보드 형태로 확장
- 루트 2: PyQt/PySide 기반 데스크톱 UI
- 루트 3: Flask/FastAPI 기반 웹 대시보드

결론:
- 현재 프로젝트 일정과 안정성, FPS 리스크를 고려하면 루트 1이 가장 타당함.
- 루트 2는 시간 여유가 있을 때만 고려 가능.
- 루트 3은 사실상 새 프로젝트 수준이라 현재는 비추천.

3. 실제로 적용했던 방향
- 작은 카메라 창 하나만 띄우는 대신, 더 큰 캔버스를 만든 뒤
  - 좌측: 카메라 영역
  - 우측: 정보 패널
  구조로 바꾸는 방향을 시도함.
- 이 과정에서 camera 영역을 조금 줄이고 우측 패널을 넓혀서 정보 전달력을 높이는 방향이 맞다고 판단함.

4. 중간 문제
- 처음 대형 대시보드 버전은 PIL 한글 렌더링 호출이 많아지면서 FPS가 약 3.4까지 떨어짐.
- 즉, 시각적으로는 좋아졌지만 실시간 시연용으로는 사용할 수 없는 수준이었음.

5. 이후 경량화 방향
- 대시보드 해상도 축소
- 대부분의 텍스트를 cv2.putText 기반 ASCII 텍스트로 전환
- 그래프 개수 축소
- 패널 수 축소
- 한글 텍스트는 최소한만 유지

결과:
- FPS가 다시 약 20 이상 나오는 수준까지 회복됨.

6. 발표용 UI에 대해 정리된 방향성
발표 화면은 "개발자 디버그 화면"이 아니라 "센서 융합을 직관적으로 보여주는 쇼케이스"여야 한다는 점에 합의함.

발표 기본 화면에서 강조할 요소:
- 현재 최종 결과 단어
- 최종 confidence 1개
- top-3 후보
- 실시간 센서 그래프(특히 flex)
- Vision / Glove / Overlap 같은 상태 LED

발표 기본 화면에서 숨기거나 약화할 요소:
- QUALITY 섹션의 상세 디버그 값
- PACKET, SYNC, margin, raw_conf 등 내부 개발용 숫자
- 과도한 텍스트 정보

7. 제미나이 제안에 대해 정리된 판단
좋다고 본 부분:
- 디버그성 정보는 숨기기
- 센서 그래프를 더 크게 보여주기
- confidence bar에 색을 주기
- Vision / Sensor 상태 인디케이터를 두기
- top-1 예측 결과를 더 크게 보여주기

주의한다고 본 부분:
- "Sensor Compensating..." 같은 문구는 현재 모델 내부에서 직접 추적하는 정보가 아니므로 과장 표현이 될 수 있음
- 대신 사실 기반 문구(예: VISION LIMITED, OVERLAP DETECTED, VISION + GLOVE ACTIVE)를 쓰는 게 방어에 유리함
- 한글 텍스트를 너무 많이 쓰면 다시 FPS 문제가 날 수 있음

8. 현재 run 파일에 반영된 쪽
- 발표용에 가까운 경량 대시보드 구조가 들어가 있음
- FINAL RESULT를 우측 패널에서 더 잘 보이도록 반영함
- SYSTEM STATUS + 상태 문구 + AI CONFIDENCE + TOP PREDICTIONS + LIVE SENSOR STREAM 중심으로 재배치함
- 문법 체크(py_compile)는 통과함

9. 현재 결론
- UI는 분명 발표 완성도를 올릴 수 있음.
- 하지만 현재 프로젝트의 핵심은 여전히 실험 결과, practical 데이터, 논문 스토리 정리임.
- 따라서 지금 시점에서는 UI를 더 깊게 파기보다,
  1) 현재 방향성만 문서화해 두고
  2) 실험/논문 정리로 다시 돌아가는 게 맞음.

10. 나중에 UI를 다시 잡을 때의 추천 우선순위
1) 발표 모드 / 디버그 모드 분리
2) FINAL RESULT + AI CONFIDENCE + SENSOR GRAPH + STATUS LED 중심의 최소 쇼케이스 화면 확정
3) 필요 시 IMU 시각화 추가 여부 검토
4) 최종 발표 직전에만 미세 폰트/레이아웃 조정
